# ボートレースAI予想

Boatrace Open API のデータで各艇の1着確率を LightGBM で予測し、3連単・2連単の確率と推奨買い目を
静的サイト（GitHub Pages）で公開するシステム。

## 構成

```
boatrace/
  config.py     共通設定（場名、パス、APIのURL）
  fetch.py      Boatrace Open API 取得 + gzip キャッシュ（data/raw/, git管理外）
  features.py   1行=1艇の特徴量作成（下記）
  model.py      LightGBM 1着確率モデル、Harville による3連単/2連単確率
  pipeline.py   学習・検証、当日予測、結果照合、サイト用 JSON 出力
docs/           公開サイト（index.html / app.js / style.css + data/*.json）
models/         学習済みモデル（base: 出走表のみ / full: 直前情報あり）
.github/workflows/
  update.yml    08:00〜21:40 JST に20分おき予想更新 → docs/data をコミット
  retrain.yml   毎月再学習
```

### 特徴量

すべて Open API の過去データから計算し、予測日の前日までの情報だけを使う（未来の情報が混ざらない）。

| 区分 | 内容 |
|---|---|
| 出走表 | 級別・年齢・体重・F/L・期別平均ST・全国/当地勝率・モーター/ボート2連率 |
| 直近成績 | 過去90日の勝率・3連対率・平均着順・平均ST・STのばらつき・フライング数 |
| 今節成績 | 同じ場の前日までの6日間の走数・勝率・平均着順・平均ST |
| 場×コース | 過去1年の1着/2連/3連率、決まり手別（逃げ・差し・まくり・まくり差し）の1着率、イン1着率 |
| 選手×コース | 過去1年のそのコースでの走数・1着率・3連対率・平均ST |
| 予想ST | 今節(2走以上) → 直近90日 → 期別平均 の順で推定、コース別STがあれば優先。内側の艇との予想ST差 |
| 展示タイム補正 | レース内偏差から、その場・コースの平均的な偏差（過去1年）を差し引いた値とその順位 |
| 直前情報 | 進入コース・展示ST・チルト・体重調整・風・波・気温・水温 |
| レース内相対値 | 主要指標のレース内順位・平均との差 |

コース依存の特徴量は、`base` モデルでは枠番（枠なり想定）、`full` モデルでは展示の進入コースで計算する。
今節成績は前日までのみ（当日の前半レースの結果は Open API の反映が遅れることがあるため使わない）。

### サイトの使い方

日付 → レース場 → レース の順に選ぶと、そのレースの予想（各艇の1着確率・3着内確率、3連単の確率上位、
期待値買い目、結果）を表示する。レース未指定のときは次に締切を迎えるレースを開く。
選択は URL（例: `#2026-10-24/4/1` = 平和島1R）に反映されるので、そのまま共有・ブックマークできる。
日付はカレンダーか ◀ ▶ で選ぶ。表示できるのは予想データがある日だけ（静的サイトのため、その場では計算しない）:

- **実運用**: 定期実行で締切前に公開した予想。締切後は凍結され、成績は「成績（実運用）」に集計
- **検証データ**: `python -m boatrace backfill 開始日 終了日` で作る過去日の予想。開始日より前のデータだけで
  学習したモデルを使うので、予想対象のレースはモデルにとって未知。ページ上で「検証データ」と表示し、
  成績も実運用とは別に集計する（期待値買い目は確定オッズを取得済みのレースのみ）

### 直前情報の取得と更新ボタン

Open API の直前情報は約3時間おきにしか更新されず、ほとんどのレースで締切に間に合わない。そこで
`boatrace/beforeinfo.py` が、締切45分前以内で展示タイムが未取得のレースについて公式サイトの直前情報ページ
（展示タイム・スタート展示・チルト・調整重量・気象）を取得する（1レース1リクエスト、取得済みは再取得しない）。
定期実行は10分おき（GitHub の都合で数分〜十数分遅れることがある）。

画面の「↻ 更新」ボタンは、最新の公開データを読み直す（選択中のレースはそのまま）。
静的サイトのため、ボタンを押した瞬間に公式サイトへ取りに行くのではなく、直近の定期実行で取得した内容が反映される。

### 予想の流れ

1. 朝: 出走表だけで `base` モデルが全レースを予想
2. 直前情報（展示タイム・進入コース・気象）が出たレースは `full` モデルで予想を更新
3. 締切時刻を過ぎたレースの予想は凍結（後出し防止）し、結果が出たら的中・回収を記録
4. サイトには実運用の累計成績と、学習に使っていない直近60日の検証成績を表示

## ローカルで動かす

```bash
pip install -r requirements.txt
python -m boatrace fetch 2025-01-01 2026-10-23    # 過去データ取得（約60MB）
python -m boatrace train 2025-04-01 2026-10-23    # 学習 + 検証（直近60日で評価）
python -m boatrace predict                        # 今日の予想を docs/data に出力
python -m http.server 8765 -d docs                # http://localhost:8765 で確認
```

## Web公開（GitHub Pages）

1. GitHub に public リポジトリを作り、このフォルダを push（`models/` と `docs/` も含める）
2. Settings → Pages → Source を「GitHub Actions」に設定
3. Actions タブで `update predictions` を手動実行して動作確認

以降は開催時間中（08:00〜21:50 JST）に10分おきに予想を更新し、`docs/data` をコミットして Pages に公開する。
画面（`docs/` の HTML/JS/CSS）を変更して push したときは `deploy site` が公開し直す。

## 検証結果（2026-08-25〜2026-10-23、学習に未使用の 9,135 レース）

| 指標 | full モデル | 旧版（コース別・今節・ST特徴量なし） | 参考 |
|---|---|---|---|
| logloss（1着艇の確率、小さいほど良い） | 1.1705 | 1.1841 | |
| 本命（1着確率最大）の1着率 | 57.7% | 57.4% | 1号艇固定 54.8% |
| 本命の単勝回収率 | 93.0% | 92.8% | |
| 3連単 上位5点の的中率 | 31.9% | 31.9% | |
| 3連単 上位5点の回収率 | 78.6% | 77.5% | |

的中率は1号艇固定より高いが、確率上位を買うだけでは人気サイドに寄り、控除率（約25%）を超える
回収率にはならない（そのため期待値ベースの買い目を別に出している）。
重要度の高い特徴量は 選手×コース1着率のレース内偏差、全国勝率偏差、今節平均着順偏差、場×コース1着率、内側艇とのST差。

## 期待値ベースの推奨買い目

`boatrace/odds.py` が公式サイト（boatrace.jp）の3連単・2連単オッズを取得し、
`boatrace/strategy.py` が 期待値 = 確率 × オッズ で買い目を選ぶ。

- 締切 25 分前以内のレースだけオッズを取得（定期実行1回あたり十数レース）。締切後は買い目を凍結
- モデル確率は大穴を過大評価しがちなので、オッズから逆算した市場確率と混ぜて使う
  （`model_weight`）。既定: 混合 0.5 / 期待値 1.2 以上 / 確率 1% 以上 / 最大3点
- 結果確定後に期待値買いの回収率を記録し、サイト上部に累計を表示

### 公式サイトのポリシーについて

[サイトポリシー](https://www.boatrace.jp/owpc/pc/extra/policy.html) は「大量の情報送受信及び大量のアクセス」と
コンテンツの無断複製・頒布を禁止している。このため:

- リクエストは直列・最低 1.5 秒間隔、確定オッズはキャッシュして再取得しない
- 公開サイトにはオッズ表を転載せず、推奨した買い目のオッズだけ表示する

運用前にポリシーを自分で確認し、必要なら運営元への問い合わせを検討すること。

### 期待値戦略の検証

```bash
python -m boatrace fetch-odds 2026-10-17 2026-10-23   # 確定オッズを取得（1レース約20秒、低速）
python -m boatrace backtest-ev 2026-10-17 2026-10-23  # 期間前のデータだけで学習したモデルで検証
```

期間の前半で設定を選び、後半で評価する（同じ期間で選ぶと楽観的になるため）。
注意: 検証は確定オッズを使うが、実運用は締切前オッズで判断するので結果はずれる。
3連単は的中が少なく回収率の振れ幅が大きいので、数千レース以上で判断すること。
